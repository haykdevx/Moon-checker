## Named rules

| Rule | Kind | Meaning | Legitimate lookalikes | Limits |
|---|---|---|---|---|
| `files:known-cheat-hash` | DETECTION | The file's SHA-256 equals a sample a maintainer classified as a cheat. | None for the exact file; a hash identifies content, not who put it there. | Possession, not proof of use. Any rebuild of the cheat has a new hash. |
| `environment:virtual-machine` | CONFIGURATION | The checker ran inside a virtual machine. | Players testing the checker; the gaming PC may be a different machine. | Lowers assurance: the inspected system may not be the one used to play. |
| `kernel:boot-integrity-weakened` | CONFIGURATION | Boot options weaken kernel integrity (e.g. integrity checks disabled). | Debugging setups, old tweak guides. | Lowers assurance; never a verdict. |
| `kernel:dse-off` | CONFIGURATION | Driver signature enforcement is off. | Driver development. | Lowers assurance; never a verdict. |
| `kernel:tainted` | CONTEXT | The Linux kernel reports taint flags. | NVIDIA's proprietary driver on almost every gaming PC. | Context only. |
| `kernel:hidden-process` | CONCEALMENT | A process the Linux kernel component lists is absent from /proc, re-checked after the diff. | PID namespaces (the checker running inside a container) and races the re-check did not catch. | Review required. A kernel-mode rootkit can hide from both views, so an empty diff proves nothing. |
| `kernel:driver-outside-windows` | INDICATOR | A Windows kernel module was loaded from outside the Windows folder (from the kernel component's module list). | Anti-cheats of other games, VPN, virtualisation and peripheral drivers under Program Files. | LOW severity: listed for the reviewer, never a reason to review on its own. |
| `kernel:module-hidden` | CONCEALMENT | A kernel module appears in one view and not another. | Modules loading or unloading during the scan. | Review required. |
| `steam:vac-ban` | CONTEXT | An account that logged in on this PC has a VAC ban on record. | Shared PCs, bought second-hand accounts. | History, not evidence of current cheating. |
| `steam:multiple-accounts` | CONTEXT | Several Steam accounts have logged in on this PC. | Family PCs, internet cafés. | Context only. |
| `kernel:vulnerable-driver` | INDICATOR | A driver on the vulnerable/mapper list sits in a user-writable folder (Temp, AppData, Downloads, Desktop) or an unusual one — where a cheat loader drops a driver it abuses (BYOVD). | A portable hardware tool run from Downloads can load its driver from there. | User-writable location: the rule's severity. Unusual location: MEDIUM. A manual-mapper name is never legitimate. |
| `kernel:vulnerable-driver-installed` | CONTEXT | A driver on the vulnerable list is installed in a Windows or program folder by the software it belongs to (MSI Afterburner, RGB and fan-control tools, motherboard suites, another game's anti-cheat). | This is the lookalike: everyday gaming software. | Context only; the same driver in a user folder is kernel:vulnerable-driver. |
| `kernel:driver-blocklist-off` | CONFIGURATION | Microsoft's vulnerable-driver blocklist was switched off (VulnerableDriverBlocklistEnable=0). | Some old hardware tools ask users to turn it off. | Lowers the assurance of the scan; never a verdict. |
| `kernel:platform-posture` | CONTEXT | The PC's security settings in one line: Secure Boot, memory integrity, VBS, vulnerable-driver blocklist and TPM on Windows; Secure Boot, lockdown, module signing and ptrace scope on Linux. | Most gaming PCs run with some of these off. | Context for the reviewer; says how much a kernel-level cheat would have to defeat. |
| `files:alternate-data-stream` | INDICATOR | A file carries a hidden NTFS stream: named like a cheat (CRITICAL), large enough to hold a program (≥32 KiB, HIGH), otherwise small (LOW). | Windows, browsers, antivirus and sync tools write small streams (Zone.Identifier, SmartScreen, KAVICHS, Dropbox, Mac metadata) — these are skipped while small. | Streams under allowlisted paths are skipped unless named like a cheat. |
| `defender:game-hack-detected` | INDICATOR | Windows Defender's history holds a detection of a game hack, cheat engine, trainer or HackTool DLL injector, or a file whose path matches a cheat rule. | Single-player trainers are MEDIUM. | Only what Defender saw and recorded; a history cleared by the user is empty. |
| `defender:other-hacktool` | CONTEXT | Defender recorded a HackTool that is not about games: Windows/Office activators, keygens, cracks. | Software piracy is common and unrelated to cheating in CS2. | Context only. |
| `defender:realtime-off` | CONFIGURATION | Defender real-time protection is turned off by a setting. | Many gamers turn it off for performance; a third-party antivirus does not change this setting. | Lowers the assurance of the scan; never a verdict. |
| `antiforensic:fresh-install` | CONCEALMENT | Windows was installed in the last 7 days and there is no sign of an in-place upgrade. | A new PC or a reinstall after a hardware change. | MEDIUM: asks for a look. |
| `antiforensic:feature-update` | CONTEXT | Windows was upgraded in place in the last 7 days (feature update), which rewrites the install date. | This is the lookalike of a reinstall. | Context only: history from before the update may be shorter. |
| `cs2:unsafe-launch-option` | CONFIGURATION | CS2 is set to start with an option that lowers protection: -insecure (VAC off), -allow_third_party_software, -tools, -nosteam. | Map makers use -tools; offline practice and demo tools use -insecure or allow third-party software. | Lowers the assurance of the scan; never a verdict. |
| `cs2:unsigned-binary` | INDICATOR | A program library in CS2's bin folders carries no code signature. | CS2 ships some third-party libraries; compare the name with a clean install. | LOW until measured on real installs; the check sees whether a certificate is present, not whose it is. |
| `cs2:config-script` | INDICATOR | A CS2 config contains a movement or fire script pattern (bunny-hop, jumpthrow, auto-fire alias). | Practice configs and scroll-jump binds are common and allowed on many servers. | LOW: shown to the reviewer; the server's own rules decide. |
| `cs2:module-cheat-name` | INDICATOR | A module loaded into cs2.exe is named like a cheat. | None expected. | CRITICAL; a renamed cheat is caught by the folder rules instead. |
| `cs2:module-user-folder` | INDICATOR | A DLL loaded into cs2.exe comes from Temp, Downloads, the Desktop, AppData or another user folder — how most internal cheats get in. | Overlays that live in AppData are recognised by their DLL name (Discord, Overwolf, Medal). | HIGH; manually mapped cheats do not appear in the module list. |
| `cs2:module-unusual-folder` | INDICATOR | A DLL loaded into cs2.exe comes from a folder that is not the game's, Windows' or a program folder. | A tool installed to its own folder on another drive. | MEDIUM: asks for a look. |
| `cs2:modules-context` | CONTEXT | Overlays and program libraries loaded into the game, listed for the reviewer. | This is the lookalike list. | Context only. |
| `cs2:overlay-window` | INDICATOR | A transparent, always-on-top window covers the game and belongs to a program that is not a known overlay — the shape of an external ESP. | Rare overlays not on the list (a stream widget, a crosshair app); the owning program is named in the finding. | MEDIUM (HIGH from a user folder); ESPs drawn through a DirectX hook have no window. |
| `cs2:not-running` | CONTEXT | CS2 was not running, so the live checks did not run. | — | Ask the player to start CS2 and run the check again to see what is loaded into the game. |
