## 2. Findings — ordered by severity

### Correctness of verdicts (violates the brief)
1. **Weighted evidence sum counts correlated signals as independent proof.**
   `ScoreCalculator` adds per-finding weights (HIGH = 30, MEDIUM = 12) and crosses
   `CHEAT` at 70. One artefact typically surfaces in several collectors (file,
   Prefetch, AmCache, shellbags), so a single cause is counted several times.
2. **Missing telemetry can become a clean result.** `ScanEngine.adjustForReliability`
   only downgrades CLEAN when the process is not elevated; modules that ended in
   `ERROR`/`TIMEOUT`/`SKIPPED` still allow `CLEAN`.
3. **Security configuration alone can produce `CHEAT`.** Test-signing mode and weak
   boot options are HIGH findings; two of them plus one MEDIUM exceed the
   threshold with no evidence of cheating.
4. **Every CRITICAL forces `CHEAT`,** including heuristics escalated to CRITICAL
   (e.g. name matches promoted by `escalate()`), so a single filename match is
   treated as validated.

### Kernel components
5. `MoonMon.c` creates its device with `IoCreateDevice` and no security
   descriptor — any local user can open it and issue the IOCTL.
6. `MoonMon.c` truncates silently when the caller's buffer is too small and still
   returns `STATUS_SUCCESS`; the client cannot tell the list is incomplete.
7. `MoonMon.c`'s header claims kernel-mode enumeration defeats hiding. It reads
   `PsLoadedModuleList` (the same data user mode can query); a manually mapped
   driver never appears there. The claim must be removed.
8. `moonmon.c` prints `task->comm` unescaped; a process can rename itself to
   embed a newline and forge extra report lines.
9. Neither component is signed, versioned in the report, or covered by an
   install/uninstall procedure.

### Report integrity and trust
10. The HMAC key is compiled into the client, so the embedded HMAC proves only
    that a report was not edited by hand. The panel already treats the session
    token (issued at claim time) as the binding; the schema should say so and
    stop presenting the HMAC as authenticity.
11. No collector/rule versions per finding, no provenance, no coverage section,
    no explicit consent record in the report.
12. No signed update channel for the checker or rules; the version floor exists
    only as a server setting.

### Hygiene
13. Two editor-tool cache files under `src/main/resources/{fonts,i18n}/` (since removed)
    are editor-tool logs (they contain a developer's local file paths) and ship
    inside the jar.
14. No `README` / build instructions at the repo root.

### Web panel (built in the previous task)
15. Missing workflows the brief requires: appeals, a player-facing session status
    page, rule explanations, evidence timeline on the web, data export/deletion
    per player, and a clear "demo data" separation.
